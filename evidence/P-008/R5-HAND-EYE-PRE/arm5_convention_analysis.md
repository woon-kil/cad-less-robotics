# Arm5 convention

계획 URDF `Arm5_Joint` axis는 `0 1 0`이다. 부모는 `Arm4_Link`이고 origin rpy는 `0 0 0`이다. 이 축은 `base_link`의 Y가 아니다. Arm4 원점 rpy가 `1.57079632679386 0 0`이라, Arm5의 Y는 그 앞 프레임 안에서 정의된다.

Drive의 공식 URDF는 같은 관절의 axis가 `0 -1 0`이다. 공식 파일이 정답이라고 두지 않는다. 런타임 KDL이 읽는 설치 파일은 계획 모델과 같은 sha256이고 axis는 `0 1 0`이다.

드라이버는 id 5에 `180 - pos`를 넣지 않고, `(degree - 90) * pi/180`만 적용한다. 이 식은 제조사 axis의 마이너스를 상쇄하지 않는다. 런타임 사슬은 계획 모델의 +Y를 그대로 쓴다.

축을 `0 -1 0`으로 바꾸면 관절 원점의 위치는 그대로다. 회전 방향만 반대가 된다. 라이브러리 93°는 URDF로 3°이고, 두 축의 자세 차이는 6°다. 그 자세의 정지 사진으로는 두 축을 구분하지 못한다.

P-006B는 id 1~5의 순서를 강좌의 아래→위와 맞췄고, 움직임을 만들지 않아 `UNVERIFIED`로 남겼다. 그 뒤의 동작 게이트는 ID2만 움직였다. Arm5의 실제 회전 방향을 FK와 비교한 기록은 없다.

```text
ARM5_CONVENTION_RESOLVED = NO
```

URDF는 수정하지 않았다.
