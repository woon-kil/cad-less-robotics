# 0x1c

주소는 `0x15`다. 설치 파일 `/home/jetson/dofbot_pro/Arm_Lib/Arm_Lib/Arm_Lib.py` 78행에서 83행만 이 레지스터를 쓴다. 같은 파일에 `0x1c` 읽기는 없다.

쓰는 값은 편차 각도가 아니다.

- id가 1에서 6이면 그 서보 id를 한 바이트로 쓴다.
- id가 0이면 `0x00`을 쓴다.

소스 주석은 id 1–6을 중위 편차 설정, id 0을 초기 복귀로 적는다. 공식 캘리브레이션 설명과 설치 노트북도 같다. MCU가 그 id의 현재 각을 읽어 범위 안이면 저장하고, 범위를 넘거나 id가 없으면 저장하지 않는다. id 0은 저장 편차를 지우고 기본으로 되돌린다.

그래서 `0x1c`는 세 가지가 아니다.

- 편차 숫자를 실어 보내는 데이터 레지스터가 아니다.
- 상태 읽기가 아니다.
- 저장된 편차 숫자를 읽는 레지스터가 아니다.

분류는 `STATE_MUTATING_WRITE`다. 쓰기는 저장 또는 삭제의 트리거다. 저장이 MCU에 남는다는 설명은 벤더 문서와 주석에 있고, 이번 게이트는 그 쓰기를 실행하지 않았다. EEPROM이라는 장치 이름은 설치 소스에 없으므로 persistence 위치는 `VENDOR_DOCUMENTED`이고 칩 종류는 확정하지 않는다.

직전 설정의 성공 여부는 다른 레지스터다. `0x1b`는 89행에서 `0x01`을 쓴 뒤 바이트를 읽으며, 주석의 반환은 0, 1, 2다. 이것은 방금 한 설정의 결과이지, 지금 저장돼 있는 편차의 크기가 아니다.
