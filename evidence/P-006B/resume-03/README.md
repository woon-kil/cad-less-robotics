# P-006B-R3

로봇은 움직이지 않았다. 컨트롤러 각도는 `Arm_serial_servo_read`로 세 번 다시 읽었다. 세 세트 모두 ID1~ID6이 86, 150, 0, 18, 93, 178이었다. resume-01 숫자와 같지만, 그 파일을 현재값으로 쓰지 않았다.

후보 식 `q = (library_deg - 90°) × π/180` 을 P-002에 기록된 URDF 관절값에 넣어 FK를 계산했다. 그림은 `visualizations/`의 막대 그림이고, 사진 픽셀에 맞추지 않았다.

고정 Gemini 화면에는 팔 링크가 없다. 기존 `evidence/P-006A/gemini-color.png`와 R2의 robot_side, camera_side 컬러 프레임이 그 시야다. 카메라 노드는 이번 읽기 때 publish 중이 아니었고, 같은 고정 시야를 다시 켜도 링크가 새로 들어오지 않는다. 팔이 보이는 동기 사진은 없다.

그래서 관절 convention은 모두 `INSUFFICIENT_VISIBILITY`다. P4-CONVENTION도, 정밀 calibration도 없다.

한계만 보면 H1(오프셋 없음)은 Arm2가 URDF 상한을 약 60° 넘긴다. H0과 부호를 뒤집은 H2는 한계 안이다. 사진이 없어 둘 중 어느 쪽이 실제 굽힘인지는 가르지 못한다.

판정은 **BLOCKED**다.

다음 정적 사진이 있으면 이 비교를 다시 열 수 있다. 로봇, Gemini, LED는 그대로 둔다. 휴대폰 위치는 보정 프레임이 아니다.

1. 팔의 굽힘 평면 옆에서, 베이스부터 그리퍼까지 한 프레임에 들어오게.
2. 베이스 위에서 Arm1 회전이 테이블의 로봇→카메라 방향과 어떻게 어긋나는지 보이게.
3. 그리퍼 쪽에서 베이스를 바라보며 손목 방향이 보이게.
