# servo ping semantics (스펙 §17)

## 공식 근거 — 없음

`Arm_ping_servo` 와 `0xDA` 는 공식 자료 14종 어디에도 등장하지 않는다. Orin판 `17. Basic Control Course` 는 1~12번 코스(RGB·부저·단일서보·읽기·6축 time·6축·댄스·메모리동작·블록집기·운반·쌓기·2대동기)로 구성되며 **ping 코스가 존재하지 않는다.**

→ **`NOT_DOCUMENTED_IN_OFFICIAL`**

## P-007C 의 ping 결과가 증명하는 것의 범위

P-007C 실측: ID1~6 전부 `0xDA`.

공식 정의가 없으므로 이 값의 의미는 **설치본 소스의 정적 분석에만 근거한다**(P-007C `api_inventory.json`, register `0x38`). 따라서 다음으로 범위를 제한한다:

**증명하는 것**
- `0x15` 보드가 ID1~6 각각에 대한 조회 트랜잭션을 수행하고 일관된 값을 돌려줬다. 보드가 살아 있고 ID 별 경로가 동작한다.

**증명하지 않는 것**
- 🔴 서보가 **명령을 수락할 상태**라는 것. 토크 OFF 상태의 서보도 버스 상에서는 응답한다 — 공식 정의가 "does not receive the **level signal**"(구동 신호 미수신)이라고 적지 토크 OFF 에서 통신이 끊긴다고 적지 않는다. **ping 성공과 torque ON 은 다른 명제다.**
- 펌웨어가 위치 payload 를 수락했다는 것.
- 서보가 물리적으로 구동 가능하다는 것(전원·기구·부하).

이 제한은 H-C1(`ELIMINATED`)의 해석에도 적용된다. H-C1 이 제거한 것은 **통신 경로**이지 **명령 수용성**이 아니다. H-C2·H-C6 이 열려 있는 이유가 바로 이 틈이다.
