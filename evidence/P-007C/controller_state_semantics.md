# `Arm_serial_servo_read`가 읽는 것은 무엇인가

## 소스에서 알 수 있는 것 (189~217행)

```
write_byte_data(0x15, id + 0x30, 0x0)     194행   ← 조회 요청
sleep(0.003)                               195행
pos = read_word_data(0x15, id + 0x30)      196행   ← 16비트
pos == 0 이면 None                          202행대
pos = (pos >> 8 & 0xff) | (pos << 8 & 0xff00)      바이트 스왑
id == 5 : pos = int(270 * (pos-380) / 3320)        스케일 (0~270)
그 외   : pos = int(180 * (pos-900) / 2200)        스케일 (0~180)
범위 밖이면 None
id in (2,3,4) : pos = 180 - pos            212~213행  역변환
```

소스는 **컨트롤러 보드의 `0x30+id` register에서 16비트 값을 읽는다**는 것까지만 말한다. 그 값이 보드 안에서 어떻게 만들어지는지는 이 소스에 없다.

## 분류

| 후보 | 소스·문서 근거 | 판정 |
| --- | --- | --- |
| commanded position (보드가 마지막 명령을 되돌려줌) | 없음 | 배제 못 함 |
| servo feedback (서보가 보고하는 실제 위치) | 없음 | 배제 못 함 |
| MCU cached state | 없음 | 배제 못 함 |
| 물리 포텐셔미터/엔코더 직접 | 없음 | 배제 못 함 |

→ **`CONTROLLER_REPORTED_STATE` 유지.** encoder feedback으로 승격하지 않는다. P-006B·P-007A가 쓴 표현을 그대로 둔다.

## P-007B가 이 분류에 주는 간접 증거

P-007B에서 `write(2, 152)` 후에도 readback이 150이었다. 만약 이 값이 **단순히 마지막 명령을 되돌려주는 것**이라면 152(또는 절단으로 153)가 나왔어야 한다. 나오지 않았다.

이것은 두 가지 중 하나를 뜻한다.

1. 읽는 값이 commanded position이 아니다(= 서보·보드의 상태 쪽에 가깝다), 또는
2. 명령 자체가 보드의 목표 레지스터에 반영되지 않았다.

**이 둘을 구분할 수 없다.** 그래서 이 증거로 분류를 승격하지 않는다.

## 지터 관찰

P-007A부터 P-007C까지 약 10시간 30분, 1,290+ 샘플에서 6채널 전부 unique 1개로 완전 고정이었다.

```
2026-10-26T22:58  [86,150,0,18,93,178]   (P-007A)
2026-10-27T08:36  [86,150,0,18,93,178]   (P-007A-R1 격리 후)
2026-10-27T09:22  [86,150,0,18,93,178]   (P-007B baseline)
2026-10-27T09:28  [86,150,0,18,93,178]   (P-007B 명령 후)
2026-10-27T09:4x  [86,150,0,18,93,178]   (P-007C 조회 전후)
```

한계: 1 library degree = raw 12.22 counts다. 따라서 **±6 counts 수준의 아날로그 지터는 degree 단위에서 보이지 않는다.** 완전 고정이 "라이브 피드백이 아니다"의 증거가 되지 못한다. raw 워드를 변환 전에 로깅하면 이 구분이 가능하지만, 그것은 `0x30+id` 트랜잭션과 바이트 동일한 조회이므로 다음 게이트에서 판단할 사항으로 남긴다(이번 게이트는 스펙 §17의 raw protocol 실험 금지를 넓게 해석해 실행하지 않았다).
